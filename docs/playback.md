# 再生

## 再生できる形式

| 何 | 形式 | 選び方 |
| --- | --- | --- |
| ライブ・追っかけ | 元の TS (MPEG-2)、または fragmented MP4 (H.264 / AV1 / H.265) | 操作の列の「画質」(自動 → AV1 → H.264 → MPEG-2)。自動は denpa が選ぶ (下の「自動」) |
| 録画 | エンコード済みのファイル (Matroska、AV1 / H.265 / H.264)、または denpa に流してもらう元の TS (MPEG-2)・fragmented MP4 (H.264 / AV1 / H.265) | denpa が選ぶ (下の「録画」) |

Media3 で何をどう読むかは [libraries.md](libraries.md#media3-で何が再生できるか)。

## 自動

**どの形式で流すかは denpa が選びます。** テレビは順番を持たず、再生できる形式を denpa に伝えるだけです
(denpa の docs/api.md の「形式をサーバに選ばせる `codec=auto`」)。ライブ・追っかけは `?codec=auto&playable=…`、録画は `playback?playable=…` の `auto` です。
denpa は画面の「自動」と同じ順 (家の中か・GPU でエンコードできるかも denpa が見る) で、`playable` にある最初のものを選びます。

- `playable` に並べるのは、**ハードでデコードできる** MPEG-2 (`raw`)・AV1・H.265 と、H.264 (どの端末もデコードできる)。
  ソフトの AV1 / MPEG-2 デコーダを持つ端末もあるが、1080 を流しっぱなしでデコードするには非力なことが多い (Chromecast with Google TV の AV1 など)。
  起動したときに端末のデコーダを調べて決める (`data/Codecs.kt` の `Playable`)
- denpa が選んだ形式は応答ヘッダ `X-Denpa-Codec` で受け取る。**溜め方 (MPEG-2 は少なく溜める。下の「MPEG-2」) と遅れたときの追いつき方は、このヘッダで切り替える。**
  開いたあとにリクエストし直したり、プレーヤーを作り直したりはしない (`ui/Player.kt` の `BufferingControl`)。字幕のストリーム・音声の選び方も、受け取った形式に合わせる
- denpa が H.265 を選んだライブでは、字幕と実況のコメントが出ない (denpa のライブの字幕のエンドポイントが H.265 を受けないため。字幕と実況は、映しているコマの時刻をそのストリームから受け取る)
- 自動のボタンには、denpa が選んだ形式を添えます (「自動 (MPEG-2)」)。応答が届くまでは「自動」だけ
- **端末の側で再生できなかった形式**は、その画面を開いている間だけ `playable` から外して、リクエストし直します (覚えない)。
  デコーダを作れない・形式に対応していない (Media3 の 4001・4004・4005) か、データが 1 秒ぶん溜まってから 15 秒たっても最初のフレームが出ないときです (回線が遅くて溜まらない間は数えない)。
  denpa の側で止まったもの (200 で中身が空のまま閉じた・5xx) は、同じ `playable` でリクエストし直します (denpa が GPU の降りた経路を避けて次のものを選ぶ)。
  外していって `playable` が空になったら、止めて「再生できる形式がありません」。denpa が選べなかった (406) ときも同じ文を出します
- denpa の変換の枠が埋まっていれば 503 で断られる (ほかの形式には移らない)。何度かリクエストし直し、だめなら「サーバが混んでいます」
- 「画質」のボタンはブラウザのコーデックのメニューと同じ並び (自動 → AV1 → H.265 → H.264 → MPEG-2) から、テレビで選べないものを外したものです。
  AV1 と MPEG-2 はハードでデコードできる端末だけ、H.265 はいつも外します (選ぶのは denpa の自動だけ)
- ライブで選んだものは、家の中でも外でもそのまま使います (テレビごとに覚える)。自動を選ぶと覚えていた選択を消し、開くたびに denpa に選ばせます (選ばれた形式は覚えない)。
  追っかけは開くたびに自動から始め、選んだものは開いている間だけです (ブラウザと同じ)
- 世帯の設定の「コーデックの選択肢に H.264 と H.265 を出さない」(`api/playback/options` の `hidden`) なら、H.264 のボタンを出しません。
  外すのはボタンだけで、自動では今までどおり `playable` に H.264 を入れます (AV1 を流せない端末には H.264)。H.264 を選んでいたテレビは自動として扱います

## 録画

開くたびに denpa に**何で観るか**を選ばせます (`GET api/recordings/<id>/playback?playable=…` の `auto`)。

- `{"way":"file"}` は**エンコード済みのファイル**をそのまま読む (`file?source=`)。denpa は読んで渡すだけ
- `{"way":"stream"}` は fragmented MP4 で流してもらう (`stream?codec=`。詰め替えか変換)、`{"way":"raw"}` は元の TS をそのまま流してもらう (`stream?codec=mpeg2`)。
  変換は denpa がその場でエンコードするので、同時に変換できる本数を超えて断られたら何度かリクエストし直し、だめなら「サーバが混んでいます」(追っかけと同じ)
- **denpa が選べなかった (`auto` が `null`) ときは、ソフトでデコードできるもの (AV1・MPEG-2) を `playable` に足して聞き直す。**
  カクカクすることはあるが、観られないよりよい。それでも選べなければ「再生できる形式がありません」
- 端末の側で再生できなかった形式は、ライブと同じくその画面を開いている間だけ外して聞き直す。聞き直したものは、外す前の位置から開く

エンコード前・エンコードに失敗した録画 (元の TS しか無い) も、MPEG-2 のデコーダが無い端末で観られます (denpa が変換して流す)。

- ファイルはシークをプレーヤーがする。チャプター (CM 飛ばし) は動画に入っているもの
- denpa に流してもらうときは流しっぱなしの1本なので、**シークは位置を変えてリクエストし直す** (左右を続けて押したぶんはまとめてリクエストする)。
  尺は `playback` の尺、チャプターは `api/recordings/<id>/chapters`。CM を飛ばすのもリクエストし直しで、元の TS から流すときは
  denpa がリクエストした位置の 1 秒手前から流すので、そのぶん先をリクエストして CM の終わりを映さない
- 位置・尺・チャプター・続きの位置は、どれも録画の時刻 (`playback` の基準) で数える。ストリームはリクエストした位置ちょうどからは始まらないので、
  Extractor が頭を 0 に寄せた幅から録画の時刻に戻す ([libraries.md](libraries.md#media3-で何が再生できるか))
- 観た位置を預ける (`POST api/recordings/<id>/resume`) ときは、観ているファイルを `source` で添える。ファイルはそのファイル (`encoded` / `alt`)、
  流してもらうときは元にしたファイル (`playback` の基準。エンコード済みがあれば `encoded`、無ければ `ts`)、追っかけは `ts`。
  denpa は元の TS の時刻に直して覚え、一覧の `resumeMs` はエンコード済みの時刻 (無ければ元の TS の時刻) で返す。
  追っかけからエンコード済みのファイルに移るときは、いまの位置を `ts` で預けて一覧を読み直し、直った位置から開く
  (CM を切ったもの・頭を捨てたものは時刻が合わないため)
- ストリームが終わりより手前で終わった・切れた・止まったら、いた位置からリクエストし直す (追っかけと同じ決まり)。裏に回ったら denpa への接続を閉じ、戻ったらいた位置からリクエストし直す

## MPEG-2 (いちばん遅れが少ない)

denpa にエンコードさせず、放送そのもの (1局に絞った TS) を流します (`?codec=raw`。自動で denpa が選んだときも同じ)。エンコードを待たないぶんいちばん早く映り、
denpa の CPU も使いません。溜める量も小さくし (0.5〜2 秒、0.25 秒溜まったら映す)、遅れたら少し速く回して追いつきます (応答ヘッダ `X-Denpa-Codec` が `raw` のとき)。

- 字幕は選局の直後などに少し遅れて出ることがある
- **MPEG-2 をハードでデコードできる端末だけ**選べ、自動の `playable` にも入れる (起動時に端末のデコーダを調べる)
  - Fire TV は公式の仕様に MPEG-2 のハードデコードが載っている
    ([Amazon のデバイス仕様](https://developer.amazon.com/docs/device-specs/device-specifications-fire-tv-streaming-media-player.html))
  - Chromecast with Google TV と Google TV Streamer の公式の仕様には載っていない
    ([Google の仕様](https://support.google.com/chromecast/answer/3046409))。実機で調べて、無ければ選べない
  - 地デジのチューナーを内蔵したテレビは持っていることが多いが、アプリに使わせるかは機種しだい
- 音声は放送の AAC のまま (端末のデコーダでデコードする)。番組の途中で 5.1ch とステレオが入れ替わると、一瞬途切れることがある

## 切れたとき

- **ライブ・追っかけが切れたら自分で繋ぎ直す**。denpa がストリームを閉じた (番組の境目の再エンコード・GPU からソフトウェアへ降りた・再起動)・
  読めなくなった・**10 秒進まない** (チューナーのドライバが黙った) のどれでも、ライブは同じ局を、追っかけはいた位置からリクエストし直す。
  待ちは 1 秒から倍々で 10 秒まで、**回数の上限は無い** (点けっぱなしで戻ってきたときに映っていてほしい)。
  その間は前の映像のまま、1.5 秒たったら読み込み中の印と「繋ぎ直しています」を出し、画面も点けたまま
- **番組が替わって映像・音声・字幕の並び (PMT) が変わったときも、denpa は H.264 / AV1 のライブ・追っかけを閉じる** (MPEG-2 は閉じない)。
  ライブはすぐ同じ局を、追っかけは届いたぶんを観終えてから観ていた位置をリクエストし直す。映れば数え直すので、番組が何度替わっても回数を使い切らない。
  ただしライブが 30 秒以内に続けて閉じたら、待ちを倍々に伸ばす (替わり目の前後で並びが行き来する局で、リクエストし直しを連打しない。ブラウザの denpa と同じ)。
  追っかけは録り終えたのかを denpa に聞いてから (録り終えて最後まで観たなら「最後まで観ました」)
- 局が無い (404) など待っても直らないものは理由を出して止める
- 追っかけ (譲った録画の追っかけも) の H.264 / AV1 が denpa の**変換の枠が埋まって断られた** (503 「サーバが混んでいます」) ときは、
  3 回までリクエストし直し、だめなら「サーバが混んでいます」(MPEG-2 をデコードできる端末なら MPEG-2 を勧める)。denpa の入れ替えの最中の 503 は、理由が違うのでいつもどおりリクエストし直し続ける
- denpa が**何も送らずに閉じた** (ライブはチューナーの空きが無い・放送休止など、追っかけは変換できなかった) ときは 3 回までリクエストし直し、だめなら「映像を送らずに閉じました」
- ライブが**録画にチューナーを譲った** (denpa の通知 `yielded` が来た) あとのリクエストし直しが映らなかったら、リクエストし直さずに譲った録画の追っかけへ切り替える
  ([usage.md](usage.md#ライブ))。追っかけが切れた・録り終える前に閉じたら、録れているところの少し手前からリクエストし直す。録り終えたらライブに戻る
- 録画のファイル (エンコード済み) は、回線が切れたときだけいまの位置から 3 回まで読み直す。denpa に流してもらう録画は、追っかけと同じくいた位置からリクエストし直す
- 繋ぎ直すたびに理由を logcat に1行出す (`adb logcat -s denpa:I`。`ended` = denpa が閉じた、`stall` = 進まない、
  `error=…` = 読めない・HTTP の番号)。不具合を知らせるときに添えてください

## ほか

- 映像を流している間はスクリーンセーバーを出さない (止めた・観終えたら出る)
- **ホームを押す・別のアプリに替えると止める**。ライブは denpa への接続を閉じて (チューナーを空ける) 戻ったら同じ局を映し直し、
  録画は観た位置を預けて (「続きを視聴」にも出る) 戻ったら続きから。追っかけも観た位置からリクエストし直す
