# 再生

## 再生できる形

| 何 | 形 | 選び方 |
| --- | --- | --- |
| ライブ・追っかけ | 生の TS (MPEG-2)、または fragmented MP4 (H.264 / AV1) | 操作の列の「画質」。既定は端末がハードで MPEG-2 を解ければ MPEG-2、でなければ H.264。AV1 と MPEG-2 はハードで解ける端末だけ |
| 録画 | Matroska (AV1 / H.264)、生の TS (MPEG-2) | 解ける中で軽いものから: AV1 → H.264 → 生の TS |

Media3 で何をどう読むかは [libraries.md](libraries.md#media3-で何が再生できるか)。

## MPEG-2 (いちばん遅れが少ない)

denpa に焼かせず、放送そのもの (1局に絞った TS) を流します (`?codec=raw`)。焼くのを待たないぶんいちばん早く映り、
denpa の CPU も使いません。溜める量も小さくし (0.5〜2 秒、0.25 秒溜まったら映す)、遅れたら少し速く回して追いつきます。

- 字幕は選局の直後などに少し遅れて出ることがある
- **MPEG-2 をハードで解ける端末だけ**選べる (起動時に端末のデコーダを調べる)
  - Fire TV は公式の仕様に MPEG-2 のハードデコードが載っている
    ([Amazon のデバイス仕様](https://developer.amazon.com/docs/device-specs/device-specifications-fire-tv-streaming-media-player.html))
  - Chromecast with Google TV と Google TV Streamer の公式の仕様には載っていない
    ([Google の仕様](https://support.google.com/chromecast/answer/3046409))。実機で調べて、無ければ選べない
  - 地デジのチューナーを内蔵したテレビは持っていることが多いが、アプリに使わせるかは機種しだい
- 音声は放送の AAC のまま (端末のデコーダで解く)。番組の途中で 5.1ch とステレオが入れ替わると、一瞬途切れることがある

## 切れたとき

- **ライブ・追っかけが切れたら自分で繋ぎ直す**。denpa が流れを閉じた (番組の境目の焼き直し・GPU からソフトウェアへ降りた・再起動)・
  読めなくなった・**10 秒進まない** (チューナーのドライバが黙った) のどれでも、ライブは同じ局を、追っかけは居た場所から頼み直す。
  待ちは 1 秒から倍々で 10 秒まで、**回数の上限は無い** (点けっぱなしで戻ってきたときに映っていてほしい)。
  その間は前の絵のまま、1.5 秒たったら回るものと「繋ぎ直しています」を出し、画面も点けたまま
- 局が無い (404) など待っても直らないものは理由を出して止める
- ライブで denpa が**何も送らずに閉じた** (チューナーの空きが無い・放送休止など) ときは 3 回まで頼み直し、だめなら「映像を送らずに閉じました」
- 録画のファイルは、回線が切れたときだけいまの位置から 3 回まで読み直す
- 繋ぎ直すたびに理由を logcat に1行出す (`adb logcat -s denpa:I`。`ended` = denpa が閉じた、`stall` = 進まない、
  `error=…` = 読めない・HTTP の番号)。不具合を知らせるときに添えてください

## ほか

- 映像を流している間はスクリーンセーバーを出さない (止めた・観終えたら出る)
- **ホームを押す・別のアプリに替えると止める**。ライブは denpa から降りて (チューナーを空ける) 戻ったら同じ局を映し直し、
  録画は観た位置を預けて (「続きを視聴」にも出る) 戻ったら続きから。追っかけも観た位置から頼み直す
