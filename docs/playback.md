# 再生

## 再生できる形式

| 何 | 形式 | 選び方 |
| --- | --- | --- |
| ライブ・追っかけ | 元の TS (MPEG-2)、または fragmented MP4 (H.264 / AV1) | 操作の列の「画質」。既定は端末がハードで MPEG-2 をデコードできれば MPEG-2、でなければ H.264。AV1 と MPEG-2 はハードでデコードできる端末だけ |
| 録画 | エンコード済みのファイル (Matroska、AV1 / H.264)、または denpa に流してもらう元の TS (MPEG-2)・fragmented MP4 (H.264 / AV1) | denpa に何を出せるかを聞いて (`playback`)、端末がデコードできるものから (下の「録画」) |

Media3 で何をどう読むかは [libraries.md](libraries.md#media3-で何が再生できるか)。

## 録画

開くたびに denpa に**何で観られるか**を聞き (`GET api/recordings/<id>/playback`)、端末がデコードできるものから選びます。

1. **エンコード済みのファイル** (AV1 → H.264。軽いほうから)。denpa は読んで渡すだけ
2. **元の TS をそのまま** (MPEG-2 をハードでデコードできる端末)。denpa はエンコードしない
3. **denpa が変換した H.264 → AV1**。denpa がその場でエンコードするので、同時に変換できる本数を超えて断られたら何度かリクエストし直し、だめなら「サーバが混んでいます」(追っかけと同じ)
4. 元の TS を、ソフトのデコーダで

エンコード前・エンコードに失敗した録画 (元の TS しか無い) も、MPEG-2 のデコーダが無い端末で観られます (3)。
ブラウザの denpa の「自動」は MPEG-2 を最後にする (ブラウザは自分で描くので重い) が、テレビはハードでデコードできることが多いので変換より先にします。

- ファイルはシークをプレーヤーがする。チャプター (CM 飛ばし) は動画に入っているもの
- denpa に流してもらうときは流しっぱなしの1本なので、**シークは位置を変えてリクエストし直す** (左右を続けて押したぶんはまとめてリクエストする)。
  尺は `playback` の尺、チャプターは `api/recordings/<id>/chapters`。CM を飛ばすのもリクエストし直しで、元の TS から流すときは
  denpa がリクエストした位置の 1 秒手前から流すので、そのぶん先をリクエストして CM の終わりを映さない
- 位置・尺・チャプター・続きの位置は、どれも録画の時刻 (`playback` の基準) で数える。流れはリクエストした位置ちょうどからは始まらないので、
  読み手が頭を 0 に寄せた幅から録画の時刻に戻す ([libraries.md](libraries.md#media3-で何が再生できるか))
- 流れが終わりより手前で終わった・切れた・止まったら、いた位置からリクエストし直す (追っかけと同じ決まり)。裏に回ったら denpa への接続を閉じ、戻ったらいた位置からリクエストし直す

## MPEG-2 (いちばん遅れが少ない)

denpa にエンコードさせず、放送そのもの (1局に絞った TS) を流します (`?codec=raw`)。エンコードを待たないぶんいちばん早く映り、
denpa の CPU も使いません。溜める量も小さくし (0.5〜2 秒、0.25 秒溜まったら映す)、遅れたら少し速く回して追いつきます。

- 字幕は選局の直後などに少し遅れて出ることがある
- **MPEG-2 をハードでデコードできる端末だけ**選べる (起動時に端末のデコーダを調べる)
  - Fire TV は公式の仕様に MPEG-2 のハードデコードが載っている
    ([Amazon のデバイス仕様](https://developer.amazon.com/docs/device-specs/device-specifications-fire-tv-streaming-media-player.html))
  - Chromecast with Google TV と Google TV Streamer の公式の仕様には載っていない
    ([Google の仕様](https://support.google.com/chromecast/answer/3046409))。実機で調べて、無ければ選べない
  - 地デジのチューナーを内蔵したテレビは持っていることが多いが、アプリに使わせるかは機種しだい
- 音声は放送の AAC のまま (端末のデコーダでデコードする)。番組の途中で 5.1ch とステレオが入れ替わると、一瞬途切れることがある

## 切れたとき

- **ライブ・追っかけが切れたら自分で繋ぎ直す**。denpa が流れを閉じた (番組の境目の再エンコード・GPU からソフトウェアへ降りた・再起動)・
  読めなくなった・**10 秒進まない** (チューナーのドライバが黙った) のどれでも、ライブは同じ局を、追っかけはいた位置からリクエストし直す。
  待ちは 1 秒から倍々で 10 秒まで、**回数の上限は無い** (点けっぱなしで戻ってきたときに映っていてほしい)。
  その間は前の映像のまま、1.5 秒たったら回るものと「繋ぎ直しています」を出し、画面も点けたまま
- 局が無い (404) など待っても直らないものは理由を出して止める
- 追っかけ (譲った録画の追っかけも) の H.264 / AV1 が denpa の**変換の枠が埋まって断られた** (503 「サーバが混んでいます」) ときは、
  3 回までリクエストし直し、だめなら「サーバが混んでいます」(MPEG-2 をデコードできる端末なら MPEG-2 を勧める)。denpa の入れ替えの最中の 503 は、理由が違うのでいつもどおりリクエストし直し続ける
- ライブで denpa が**何も送らずに閉じた** (チューナーの空きが無い・放送休止など) ときは 3 回までリクエストし直し、だめなら「映像を送らずに閉じました」
- ライブが**録画にチューナーを譲った** (denpa の知らせ `yielded` が来た) あとのリクエストし直しが映らなかったら、リクエストし直さずに譲った録画の追っかけへ切り替える
  ([usage.md](usage.md#ライブ))。追っかけが切れたら、録れているところの少し手前からリクエストし直す
- 録画のファイル (エンコード済み) は、回線が切れたときだけいまの位置から 3 回まで読み直す。denpa に流してもらう録画は、追っかけと同じくいた位置からリクエストし直す
- 繋ぎ直すたびに理由を logcat に1行出す (`adb logcat -s denpa:I`。`ended` = denpa が閉じた、`stall` = 進まない、
  `error=…` = 読めない・HTTP の番号)。不具合を知らせるときに添えてください

## ほか

- 映像を流している間はスクリーンセーバーを出さない (止めた・観終えたら出る)
- **ホームを押す・別のアプリに替えると止める**。ライブは denpa への接続を閉じて (チューナーを空ける) 戻ったら同じ局を映し直し、
  録画は観た位置を預けて (「続きを視聴」にも出る) 戻ったら続きから。追っかけも観た位置からリクエストし直す
